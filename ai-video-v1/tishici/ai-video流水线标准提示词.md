# ai-video 视频生产流水线 · 标准提示词文档

> 用途：每次制作一个新视频时，把本文档（或本文档第七章的完整提示词模板）交给 AI Agent，按五个步骤逐段推进。核心目标：**文案（脚本/分镜） → 生图 → TTS → 动画（Remotion）**，每一步都有明确交付物和检查点。
>
> 关键原则：**先想清楚再动手**——文案阶段就要同时规划好"生图提示词、TTS 分段、屏幕大字、动画关联"，文案定稿并人工检查通过后，才进入生图和 TTS。

---

## 一、五步流程总览

| 步骤 | 做什么 | 工具/路径 | 交付物 | 检查点 |
|------|--------|-----------|--------|--------|
| 1 | 文案脚本与分镜设计 | 无（Agent 撰写） | 分镜表 + 生图提示词 + TTS 分段 + 屏幕大字 + 时长预算（**输出到新建工程根目录**） | **暂停，交用户手动检查** |
| 2 | 文生图 | `ai-video-v6/shotcraft-remotion/scripts/generate-textures.mjs`（manifest 批量 + 幂等） | 每段分镜 1 张背景图（`public/textures/`） | 图是否与文案对应、留白是否保留；被内容安全审查拦下的张数换措辞重试 |
| 3 | 旁白 TTS | `ai-video-v5/TTS/generate-tts.py`（或 generate-edge-tts.py） | 每段 mp3 + srt + durations.json | 时长回填分镜表、是否有空文件 |
| 4 | 动画设计 | **从镜头卡库随机抽签**：`ai-video-v6/shotcraft-remotion/cards/` | 抽签脚本 + 每张卡的出处/保什么/换什么 | 卡是抽的不是手挑；保留卡的动作、替换 demo 的皮肤 |
| 5 | Remotion 工程 | 在 `src/` 按标准结构建工程；卡点表驱动时间线 | Root.tsx / style.ts / SceneBg / BigText / Caption / Main.tsx + 卡点表 | **卡点不许手写**、字幕不断词、逐帧无空屏、预览 + 渲染验收 |

**通用规格**：1280×720 @ 30fps；1 帧 = 1/30 秒；时长 → 帧号换算 `round(秒 × 30)`。

> 0.5 秒 = 15 帧，但**不要**拿它当"段间必须留 15 帧"的依据 ——
> EdgeTTS 的 MP3 尾部自带约 0.5s 静音，再另加 15f 会渲出 15 帧空屏（见第九章第 4 条）。

## 二、步骤 1：文案脚本与分镜设计（最关键，先想清楚）

### 1.1 主题与文案

- **固定开场（每期必带）**：旁白第一句固定为 `局长，该学习了。今天要学习的是：#本期主题#`，再衔接钩子/正文。「#本期主题#」按本视频主题替换，整句一字不改、放最开头。
- 围绕用户给定的**本期主题**写旁白文案，口语化、有节奏，适合短视频旁白。
- **旁白限制：根据动画（分镜画面）来写旁白**——旁白描述画面里发生的事、解释画面内容，与动画强关联；**不限制字数/每段字数**，以"把该分镜画面讲清楚、和动画对得上"为准，一段对应一个分镜。
- 文案必须与主题、内容强关联，禁止跑题；同时要为后面的**生图**和**动画**留出接口（见 1.3）。

### 1.2 分镜表（核心交付物）

每个分镜一行，字段如下：

| 字段 | 说明 |
|------|------|
| 分镜号 | open / r1 / r2 / … / outro |
| 旁白文案 | 该段 TTS 要念的文字（口语化，一段一文件） |
| 生图提示词 | 英文或中英混合，见 1.3 规范 |
| 屏幕大字 BigText | 该段要打在画面上的大字（1–2 句，大字用词要短） |
| 底部字幕 Caption | **与旁白文案完全一致**（正文照抄该段旁白、不精简，底部字幕=旁白逐字数） |
| 预估时长 | 秒 → 帧数（`round(秒×30)`），作为 Remotion 时间线预算 |

> 例（时长分配参考）：open 100f + 4×185f + outro 95f ≈ 900f = 30s。

**预估时长必须按字数算，不许拍脑袋**（本流水线返工率最高的一条）：

EdgeTTS `zh-CN-XiaoxiaoNeural` + `rate=1.2` 的实测语速常数
（本仓库实测 6 段 / 447 个有效字 / 95.35s，逐段 4.43–5.01 c/s）：

```
秒  ≈ 有效字数 / 4.7      （有效字数 = 去掉标点空格后的字数）
帧  ≈ 有效字数 × 6.4
```

| 目标片长 | 可以写的有效字数 | 折合 16:9 分镜数（每段约 130–190 字） |
|---|---|---|
| 30s | ≈ 141 字 | — |
| 60s | ≈ 281 字 | — |
| 72s | ≈ 338 字 | 6 段偏紧 |
| 100s | ≈ 469 字 | 6 段舒适 |

做法：文案初稿写完后**先数字数**，再用上式反推总长，**按实测值写分镜表的"预估时长"**；
不要先定一个总时长再硬塞文案。实测语速会随文案的口语密度浮动（本片 4.43–5.01），
所以预算留 10% 余量。

### 1.3 生图提示词规范（海绵宝宝动画风）

风格约束（**每条 prompt 都要带**）：
1. **海绵宝宝动画风背景**：整体是《海绵宝宝》卡通动画片背景的画风——粗轮廓、高明度高饱和配色、水彩/动画上色质感、比奇堡海底小镇（珊瑚、水草、水母、气泡、沙地）等标志性元素。
2. **尽量还原原版画风**：画面要像原版动画的"场景背景"，不要现代 3D、不要写实、不要摄影感。
3. **仅自用**：prompt 里可注明 personal use / fan art 性质，避免商用歧义。
4. **留白构图（硬性要求）**：每张图必须留出**上下或左右的部分空白区域**，给动画叠加屏幕大字（BigText）和角色动效用。构图上"主体下方居中、上方留白"或"主体偏一侧、另一侧留白"，并在 prompt 中写明（如 `leave empty space at the top of the frame for text overlay`）。
5. **角色统一锚点（重要教训）**：如果本期主题有主要角色（如海绵宝宝大选里的海绵宝宝、痞老板等），**背景 prompt 必须点名主要角色**，且为每个角色写一段**固定外观描述**（跨场景复用，保证形象一致），不能只写环境（只写环境会生成纯背景、主要角色全部缺失）。

prompt 模板结构：

```text
SpongeBob-style cartoon background of {本期场景}，{场景细节}，
{主要角色固定锚点描述}，{角色在该场景的动作/状态}，
flat 2D animation background, thick outlines, bright saturated colors, {比奇堡标志元素},
empty space on the {top / bottom / left / right} for text overlay, personal use fan art
```

### 1.4 TTS 分段提示

- 每段旁白独立成段，**一段对应一个分镜**（名字如 `tts-open`、`tts-r1`……），方便逐段生成、逐段对齐。
- 文案要控制总时长：先按 §1.2 的语速常数（4.7 字/秒）反推，**写文案时就卡住字数**；
  EdgeTTS 实测若仍超预算，精简长段文案后重生成，再回填分镜表。
- **锁定的文案（如固定开场）要留成唯一真源**：别在 `segments.json` 里顺手"润色"
  被锁死的句子（本片踩过：锁定句是"局长，该学习了**。**……**国考省考**……"，
  录的时候变成了"该学习了**！**……**国考和省考**……"，违反"整句一字不改"）。
  正确做法是把锁定句做成常量/模板，生成 segments.json 时套用，并加一条自动比对。
- 断句用逗号/句号，避免长句一口气念不完。

### 1.5 动画关联

- 每个分镜的"屏幕大字"要在写文案时就想好：**大字内容、出现节奏（哪个词先出）、slam 落点**，与旁白语义对齐。
- 分镜之间的转场（跨骑硬切 + 闪光/水泡）在时间线编排时统一处理（见步骤 5）。
- 每段分镜之间**间隔 0.5s（15 帧）即可，不要太长**——避免节奏拖沓。

### 1.6 输出位置与检查点：完成后暂停

- **先新建本期视频工程目录**，第一步的产出**直接写到一个 md 文档**（如 `<视频>/storyboard.md`），放工程根目录：分镜表、生图提示词清单、TTS 分段（`segments.json` 内容）、屏幕大字/字幕、时长预算全部集中在这个 md 里，后续步骤直接引用。
- **该 md 定稿落盘后，先停下来交用户手动检查**，用户确认后再进入步骤 2/3。不要一口气把生图和 TTS 全跑了。

## 三、步骤 2：RunningHub 文生图

**推荐用批量脚本（manifest 驱动 + 幂等 + 顺序执行防限流）**：
`ai-video-v6/shotcraft-remotion/scripts/generate-textures.mjs`

```bash
node ai-video-v6/shotcraft-remotion/scripts/generate-textures.mjs \
  --manifest <视频>/textures.json --out <视频>/public/textures --host ai
```

- `textures.json`：`{ style: "<全片共用风格后缀>", assets: [{file, prompt, aspectRatio, resolution, quality}] }`，
  `style` 会自动拼在每个 prompt 前，scene prompt 里不要再重复。
- **幂等**：目标文件已存在就跳过，中断后重跑同一条命令即可续做；单张失败不中断，
  最后汇总失败清单。
- 实测国际站单张 20–60 秒（这是本仓库的真实速度，不是文档里的 1–5 分钟）。

单张模式（老脚本，仍可用）：`d:/APP/trae/traeProject/ai-video/ai-video-v4/runninghub-ai-image/run-image.mjs`
参考文档：`ai-video-v4/runninghub-ai-image/api接入.md`（标准模型 API 仅支持企业级-共享 API Key）

```bash
node runninghub-ai-image/run-image.mjs --prompt "<生图提示词>" [选项]
```

| 选项 | 默认 | 说明 |
|------|------|------|
| `--prompt` | 必填 | 步骤 1 生成的该分镜提示词 |
| `--aspectRatio` | `16:9` | 视频 1280×720 用 16:9 |
| `--resolution` | `1k` | `1k`/`2k`/`4k`，够用即可 |
| `--quality` | `low` | `low`/`medium`/`high` |
| `--host` | `ai` | `cn`（中国站 runninghub.cn）或 `ai`（国际站 runninghub.ai） |

执行要点：
- 每个分镜跑一次，生成结果下载到 `runninghub-ai-image/output/`。
- 生图是**异步任务 + 轮询**，单张可能 1–5 分钟（quality 高更慢），耐心等待，失败重试或调整 prompt。
- **被内容安全审查拦下时换措辞重试，不要原样重试**（详见第九章第 5 条）：
  实测含"国家/公务员/旗帜/录用通知书/厌世"等词的 prompt 会被
  `Content security audit did not pass` 拦掉，6 张拦 3 张。备一份 retry manifest。
- **图出来后人工核对**：是否与分镜文案对应、角色是否在画面里、留白区域是否保留。不合格就重新生成，不要带病进入动画阶段。

## 四、步骤 3：EdgeTTS 旁白生成

脚本位置：`d:/APP/trae/traeProject/ai-video/ai-video-v5/TTS/`
- `generate-tts.py`：通用脚本（支持 Edge/Azure/硅基/CosyVoice/Gemini/MiMo/MiniMax/ElevenLabs/Chatterbox），默认 Edge。
- `generate-edge-tts.py`：纯 edge-tts 单文件脚本，带流式超时兜底 + 重试 + 空文件清理，推荐日常用。

**推荐用 `generate-edge-tts.py`**，用法：

```bash
python generate-tts.py --segments segments.json --out <视频目录>/public/audio/tts \
    [--voice zh-CN-XiaoxiaoNeural] [--rate 1.2] [--timeout 30] [--retries 3]
```

`segments.json` 格式（每段旁白一条）：

```json
[
  {"name": "tts-open", "text": "比奇堡第一届市长竞选辩论大会，正式开始！"},
  {"name": "tts-r1", "text": "比奇堡经济低迷，水母失业……"}
]
```

| 参数 | 默认 | 说明 |
|------|------|------|
| `--voice` | `zh-CN-XiaoxiaoNeural` | 中文女声 |
| `--rate` | `1.2` | +20% 语速，与既有视频一致 |
| `--timeout` | `30` | 单次流式请求超时（秒），防挂死 |
| `--retries` | `3` | 重试次数，自动清理空文件 |

交付物：
- 每段 `tts-<name>.mp3` + `tts-<name>.srt`（词级时间轴）
- `durations.json`：各段时长（供分镜表回填帧号）

注意事项：
- **服务不稳定**（曾出现 NoAudioReceived），脚本已带超时+重试；若某段反复失败，检查网络或精简文案重试。
- 把每段实际时长 `round(秒×30)` **回填到分镜表/时间线**（Main.tsx 的 TTS 数组），确保旁白与画面时长对齐。
- 输出路径放 `<视频>/public/audio/tts/`，Remotion 里用 `staticFile('audio/tts/xxx.mp3')` 引用。

## 五、步骤 4：动画设计（从镜头卡库随机抽签）

卡库：`d:/APP/trae/traeProject/ai-video/ai-video-v6/shotcraft-remotion/cards/`

| 内容 | 路径 |
|---|---|
| 卡片总索引 | `cards/library.json`（157 张，含 summary / use / duration / energy / intention） |
| 卡片正文 | `cards/shots/<类别>/<卡名>.md`（意图 / 动效核心 / 参数表 / 已知坑） |
| 参考实现 | `cards/demos/<类别>/<卡名>/*.tsx` |
| 共享依赖 | `demos/_fixtures/Motion.tsx`（E/seg/lerp/rand + DesignStage）、`demos/_fixtures/Fixtures.tsx` |
| 整页截图素材 | `demos/_textures/`（少数卡需要，需拷到项目 `public/textures/live/`） |

> **旧版本文档里的"参考 ai-video-2"已作废**：那是上一代的样板工程，
> 照它做出来的东西每条片都长一样。动画一律从上面的卡库取。

使用规则：

1. **随机抽签，不要凭手感挑**：写个抽签脚本（固定 seed，可复现），从可移植卡池里抽。
   手挑会不自觉地挑回自己熟悉的那几张，这是"每条片都长得一样"的直接原因。
   可移植判据：demo 用 `<DesignStage>`（480×270 设计坐标等比放大）
   + 不依赖 `@remotion/motion-blur`（要另装）+ 不依赖 `_textures/`（本项目没有那些图）。
2. **先读卡 md，再读 demo 源码，最后才动手**。卡 md 里有"动效核心"（哪几个运动维度、
   各自的缓动、卡点节拍）和"已知坑"（可感下限、重复即贬值的手法）。
   只凭卡名猜实现，八成会丢掉让这张卡成立的那一个细节。
3. **保留动作内核，替换皮肤**。库里的 demo 是给产品暗场片调校的**中性灰占位件**
   （`#0a0b10` 底 + SUBJECT/OUTCOME/Dashboard/BRAND 假文案），原样贴到亮色场景上
   既不对味也读不出内容。正确做法是：把 demo 的色板/文案/底板换成本片皮肤
   （统一放一个 `skin.ts`），**动作参数表一格不动**。
   转场卡尤其要注意：它们的原底几乎都是近黑，全屏黑卡夹在明亮镜头里会读作"信号断了"。
4. **抽到的卡不够盖满整段时，拆用同一张卡的多条内核，不要另发明手法**。
   一张卡常含 2–3 段可独立使用的内核（如"骨架飞入" + "逐字 3D 落位"），
   抽到的卡少、分镜长时，把内核拆开用在不同的句子上，并在文档里写清来源。
5. **每张卡写明出处**：项目文档里逐条记录"用了哪张卡 / 保了什么 / 换成了什么"，
   便于下一条片复现抽签与判断。

## 六、步骤 5：Remotion 工程结构

工程结构按下列标准结构在 `src/` 下新建；动画组件从卡库抽签后移植（见第五章），
**不从零手写动画，也不复制其他视频项目的骨架**。

推荐用脚手架一键铺底（省掉手建工程结构这一步）：

```bash
node ai-video-v6/shotcraft-remotion/scaffold.mjs --out <视频目录> --sfx --install
```

它会拷入 `src/` 骨架（Main/Scenes/SceneBg/BigText/Caption/style）+ `src/lib/` 通用件
+ 资源目录 + `props-nobgm.json`，并在项目内 `npm install`。
**注意**：脚手架自带的 `src/skeleton/*` 是上一条片的示例内容（减肥主题），
必须整批替换成本片的卡组件；`src/lib/` 里的 3D 组件本项目用不到，
其依赖（`three` / `@react-three/fiber`）没装，记得在 `tsconfig.json` 里 exclude 掉。

视频工程建在 `src/` 下，结构：

```text
src/
├── index.ts          # 入口，注册 Root
├── Root.tsx          # 注册 Composition（id、组件、durationInFrames、fps=30、1280×720）
├── style.ts          # 色板 / 字体 / easing（本视频视觉 tokens 都放这里）
├── SceneBg.tsx       # 背景图 + 1.00 → 1.04 缓推（Ken Burns 慢推）
├── BigText.tsx       # 屏幕大字：分字入场 + slam 落地
├── Caption.tsx       # 底部字幕：对齐 TTS 词级时间轴
└── Main.tsx          # 总装：TTS + SFX 钉帧 + BGM（可关）+ 跨骑转场 + 各分镜 Sequence
```

组件要点：

| 组件 | 职责 | 技术要点 |
|------|------|----------|
| **Root.tsx** | 注册 Composition | `durationInFrames=总帧数`，`fps=30`，`width=1280`，`height=720` |
| **style.ts** | 视觉 tokens | 色板（海绵宝宝风高饱和配色）、字体、easing 曲线统一在此定义，组件引用不写死 |
| **SceneBg** | 背景 | 每分镜一张 RunningHub 图；用 `spring`/`interpolate` 做 `scale: 1.00 → 1.04` 缓推，制造运镜感；图要裁进留白构图 |
| **BigText** | 屏幕大字 | 大字**逐字/逐词入场**（分字动画），到点 `slam`（带过冲的 spring 砸下），落在图的上方留白区 |
| **Caption** | 底部字幕 | 用 TTS 的 srt 词级时间轴对齐旁白，字大（≥ 60px 档）、底部通栏 |
| **Main.tsx** | 总装 | 三段式：① TTS 数组（from + dur 来自 durations.json 回填）② SFX 钉帧表 `{from, src, volume}`（**from 一律引用卡点表，不写数值**，注释对应画面动作）③ BGM 用 `<Sequence>` 包 `<Audio>`，`bgm` inputProp 控制开/关（不需要 BGM 时整条轨去掉、连 prop 一起删干净）；④ 每分镜 `<Sequence>` 排列，**不另加段间间隔**；⑤ 跨骑转场（`<Sequence from={切点-16} durationInFrames={24}>`，窗口偏切点前侧） |

时间线规则：

- **段间间隙要单独核**：EdgeTTS 的 MP3 尾部本身带约 0.5s 静音，
  这已经就是"段间 0.5s 呼吸"。在这之上再加 15 帧，渲出来是 15 帧**纯兜底色空屏**
  （渲染 QA 会量到整帧 edge=0）。分镜直接首尾相接即可，间隙由音频尾部提供；
  若坚持加间隔，必须确认这段间隔里画面不是空的（上一镜 hold 或在转场卡覆盖范围内）。
- 转场：转场 `<Sequence>` 覆盖硬切两侧，窗口**偏切点前侧**——
  切点前压住的帧落在上一段 MP3 的尾部静音里，切点后只压几帧（<0.25s），
  否则会盖住下一句开头和刚出现的字幕。
- SFX 钉帧：`from` 不写数值，一律取卡点表里的绝对帧；SFX 在画面锁定之后再钉。

**卡点规则（本流水线最容易翻车的一环）**：

- **画面元素的出场帧一律不许手写**。"文字卡在第 8 帧入"这种写法跟旁白没有任何关系，
  实测偏差能到 1.5–7.7s，观众看到的就是"上面在动的和嘴里说的不是一回事"。
- 正确做法：写个脚本，用 srt 的**词级时间戳**反推每个关键词被念到的帧，产出一张卡点表
  （每条 `{abs, rel}`），画面/卡片/SFX 的 `from` 全部引用它。
  对齐方法：把「去掉标点的旁白全文」与「srt 词串拼接」做逐字等式校验，
  相等即可把词时间戳映射回原文每个字，再查短语起止帧。
- 加一条断言：分镜起点表与卡点表不一致就**构建期抛错**，防止改了一边忘一边。
- 配一个查词工具（`--find "某个词"` 打印它被念到的帧号），调卡点时随手可查。

**字幕规则**：

- 底部字幕 = 旁白全文照抄，但**必须切块显示**（一段 60–110 字铺满屏读不了）。
- **只在标点处切，不按字数硬切**。中文没有空格，"每块 ≤14 字"会切出
  「招|录」「三|月」「上|岸」这种断词读法，还会产出 1 个字、只显示几帧的碎块。
  规则：句末标点（。！？）基本总切；逗号类（，、：；）累计到 9 字左右才切；
  字数上限只当安全阀（26 字左右），用来兜"整段没标点"的极端情况。
- 块的时间轴来自 srt 词级时间戳，不是按字数平均分配。

渲染命令（参考骨架）：

```bash
# 预览
npx remotion studio src/index.ts

# 渲染成片
npx remotion render src/index.ts <CompositionId> out/<name>.mp4

# 无 BGM 版（Windows 必须走 props 文件，不能内联 JSON）
npx remotion render src/index.ts <CompositionId> out/<name>-nobgm.mp4 --props=props-nobgm.json
# props-nobgm.json 内容：{"bgm":false}
```

## 九、踩坑经验（历史沉淀）

1. **角色必须点名**：角色驱动的视频（如海绵宝宝大选），背景 prompt 只写"海底小镇/商业街/工地"等环境会得到纯背景、主要角色全部缺失。必须用角色统一锚点 + 场景点名出场角色。
2. **时长预算要按字数算，不许拍脑袋**：先定"全片 71.5s"再往每段塞文案，实测必然超。
   实测语速常数 **4.7 有效字/秒**（XiaoxiaoNeural +20%，本仓库 447 字 / 95.35s）；
   `秒 ≈ 有效字数 / 4.7`。某片按 2145 帧（71.5s）预算写文案，实际上限只有约 338 字，
   文案写了 447 字 —— **实测 98.3s，超 41%**，整个时间线返工。写完文案先数字数。
3. **TTS 服务不稳定**：edge-tts 曾出现 NoAudioReceived，脚本必须带超时+重试（generate-edge-tts.py 已内置）。
4. **段间间隙不要再另加**：MP3 尾部自带约 0.5s 静音，这已经是"段间 0.5s 呼吸"。
   在这之上再加 15f，渲出来是 **15 帧纯兜底色空屏**（逐帧扫描量到整帧 edge=0）。
   分镜首尾相接即可；间隙长是节奏拖沓，间隙"空"是穿帮。
5. **生图会被平台内容安全审查拦**：含"国家/公务员/旗帜/录用通知书/厌世"等词的
   prompt 会被 RunningHub 拦掉（`Content security audit did not pass`），实测 6 张拦 3 张。
   处理：备一份 retry manifest，**换措辞重试，不要原样重试**（去掉敏感词、强情绪词改中性）；
   幂等脚本会自动跳过已成功的图。
6. **锁定的文案不许"润色"**：固定开场这类"一字不改"的句子要留成唯一真源（常量/模板），
   `segments.json` 由它生成。某片手写 segments.json 时把"该学习了**。**…**国考省考**…"
   写成了"该学习了**！**…**国考和省考**…"，违反锁定规则，只能重录。
   加一条自动逐字比对，别指望验收清单里的人眼勾选。
7. **画面卡点不许手写帧号**（本流水线返工率最高的一条）：把"文字卡在第 8 帧入"
   写死，等于和旁白脱钩。实测偏差 **1.5–7.7s**（如"中央机关"该在第 119 帧出现，
   却写在第 8 帧），观众看到的就是"上面动的和嘴里说的不是一回事"。
   正确做法：用 srt 词级时间戳反推每个关键词被念到的帧，产出卡点表，
   画面/卡片/SFX 的 `from` 全部引用它；再加构建期断言防止两边不一致。
8. **字幕不许按字数硬切**：中文没有空格，"每块 ≤14 字"会切出「招|录公务员」「三|月」
   「更|高」「上|岸」这种断词读法，还产出过 1 个字、只显示 7 帧的碎块。
   只在标点处切（句末必切、逗号类累计 ≥9 字才切），字数上限只当安全阀。
9. **动画不要凭手感挑，从卡库随机抽签**：手挑会不自觉地挑回熟悉的那几张，
   结果是"每条片都长得一样"。写固定 seed 的抽签脚本，从"可移植卡池"里抽
   （判据见第五章），结果可复现。也不要再参考 ai-video-2 那套旧样板。
10. **移植卡要换皮肤，别用 demo 的舞台**：卡库 demo 是给产品暗场片调校的中性灰占位件
    （`#0a0b10` + SUBJECT/OUTCOME/BRAND 假文案）。保留**动作参数**、替换
    **色板/文案/底板**，统一放一个 skin 文件。转场卡原底几乎都是近黑，
    全屏黑卡夹在亮色镜头里会读作"信号断了"（实测亮度 29–74，改纸色后 100–227）。
11. **卡片与字幕要有布局契约**：先划清"上方大字带 / 中部卡片带 / 底部字幕带"的 y 区间，
    再摆卡片。某片 5 行网格的最后一行压进字幕带，只能改行数 + 收窄网格高度。
    转场 `<Sequence>` 也要**偏切点前侧**（切点前压在上一段尾部静音里，切点后 <0.25s），
    否则会盖住下一句开头和刚出现的字幕。
12. **引用的素材路径先验证存在**：SFX 写错子目录（`light/chime-crystal.mp3`
    实际在 `ui/`）会让整次渲染在跑到中段时崩掉，白等一次全量渲染。
    渲染前先跑一遍"表里每条 src 是否存在"的检查。
13. **组件里禁止用模块级自增计数器做随机种子**：组件每帧重渲，计数器会随之增长，
    同一个字每帧拿到不同随机参数 —— 画面乱抖且逐帧不确定（违反 Remotion 确定性渲染）。
    种子必须由文本内容哈希而来。
14. **不要把"机器能验的"当成"验收过了"**：像素指标能证明"有字、没空屏、字幕居中"，
    证明不了"角色在场、画风像不像、大字压没压住角色、多音字读得对不对、SFX 音量合不合适"。
    交付时必须把两类分开写清楚，后者明确标"待人工"，别混在"已完成"里。
